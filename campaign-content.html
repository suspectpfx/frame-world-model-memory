CONDITIONAL VALIDATION PROGRAM

Each claim has a test and a rejection condition.

Prospective design. The expanded experiments below require the stated execution gates. Existing measurements are reported in the results and visualization sections.

H1

Consumer conditioning changes the minimum feasible memory representation

  • consumer: action, future_prediction, value
  • image side: 224, 160, 112, 80, 56
  • precision bits: 8, 6, 4
  • age action steps: 0, 16, 32, 64, 128
  • prior: within_sequence_time_shuffle, independent_cross_sequence

Primary test. consumer-by-representation interaction and distinct feasible sets at calibrated task tolerances

Rejection condition. a common fixed representation meets all contracts with indistinguishable resource cost

Execution gate

consumer outputs and losses validated; train/calibration/test split frozen

H2

Unknown reversible addressing harms a spatial reader and a retained inverse restores utility

  • layout: canonical, hidden_random_permutation, inverse_materialized, inverse_fused, transpose, blocking
  • consumer: spatial_reader, permutation_invariant_control

Primary test. paired task-output loss difference and recovery equivalence with a predeclared tolerance

Rejection condition. recovery fails, or the supposed spatial consumer is invariant to the intervention

Execution gate

correctness before timing; pooling analyzed separately

H3

Layout strategies occupy different feasible storage-latency-energy points under specified workloads

  • payload bytes: 1024, 4096, 16384, 65536, 262144, 1048576, 4194304, 16777216, 67108864
  • reuse: 1, 2, 4, 8, 16, 32, 64, 128
  • consumers: 1, 3
  • rank: 8, 16, 64, 384
  • cache condition: warm, LLC_scale, beyond_LLC
  • device: CPU, GPU
  • tenancy: single, interleaved, parallel

Primary test. paired lifecycle median differences and resource feasibility; latency and energy analyzed separately

Rejection condition. reindex is practically equivalent throughout the deployment range; preservation is downgraded

Execution gate

paired kernel capabilities, hardware-counter availability and practical-equivalence margins frozen

H4

FRAME improves a closed-loop task-resource frontier under a learned world-action model

  • task: libero_spatial, libero_object, libero_goal
  • paired states per task: 40
  • memory arms: 10
  • timing modes: synchronous, latency_aware
  • planned episodes: 2400

Primary test. equal-task paired success/resource frontier; hierarchical task-then-state resampling

Rejection condition. no nondominated improvement, quality-constraint violations, or gains disappear with matched decoders and sensing

Execution gate

official or validated alternative tokenizer; stable fresh baseline; memory intervention changes executed actions; no ground-truth leakage; calibration fixed on disjoint data; stable timing and energy; sufficient successes and failures

Task is the generalization unit; initial states are paired within tasks. Confirmatory tolerances, endpoints and split assignments must be frozen before new confirmatory data collection. Exploratory screening and the pilot retain all negative outcomes.
